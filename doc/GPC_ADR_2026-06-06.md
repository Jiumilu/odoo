# GlobalCloud GPC 架构决策记录

日期：2026-06-06

## ADR-001：保留上游 Odoo 架构，仅增加 GPC 质量工具和运行态证据

状态：已采纳

### 背景

本项目目标是在当前 Odoo 19.0 仓库基础上完成 GlobalCloud GPC 品牌、中文化、运行、评估和交付闭环。当前阶段不允许重构 Odoo 核心架构，也不应在质量冲刺中引入新的业务模块边界。

### 决策

- 保留 Odoo 原生后端、前端、ORM、权限、模块加载和测试框架。
- 只在 `tools/`、`doc/`、`.github/workflows/`、`tests/` 增加本项目质量工具、证据和门禁。
- 核心业务闭环优先用 Odoo ORM smoke 证明，再用浏览器/HTTP smoke 证明入口和真实表单路径。

### 影响

- 降低与上游 Odoo 19.0 合并冲突风险。
- 质量证据可复跑、可提交、可审计。
- 深层中文化仍依赖上游翻译体系和运行态替换，不通过大规模改写核心源码解决。

## ADR-002：运行态中文化采用幂等脚本，不直接修改数据库快照

状态：已采纳

### 背景

本地数据库中存在 `YourCompany`、`OdooBot`、旧邮箱、旧电话等可见残留。直接手工修改数据库不可追踪，且无法在 CI/新环境重复。

### 决策

- 使用 `tools/gpc_apply_runtime_localization.py` 作为幂等运行态本地化入口。
- 覆盖网站、视图、邮件模板、伙伴、公司、聊天频道、历史消息等可见面。
- 将本脚本纳入 `.github/workflows/gpc-quality.yml`。

### 影响

- 新环境可重复收敛到 GlobalCloud GPC/绿色供应链公共服务平台文案。
- 本地化规则有单元测试保护，避免具体邮箱被通用域名规则提前替换。

## ADR-003：浏览器表单 E2E 标准化为仓库依赖并纳入 CI 门禁

状态：已采纳

### 背景

真实浏览器表单 E2E 能证明用户级登录、输入、保存和搜索路径。此前脚本依赖本机已有 Playwright，无法保证 CI/交付环境可复现。

### 决策

- 在本仓库提交 `package.json` 和 `package-lock.json`，固定 `playwright` devDependency。
- `tools/gpc_browser_form_e2e.cjs` 默认从本仓库 `node_modules/playwright` 加载，也允许 `GPC_PLAYWRIGHT_MODULE` 显式覆盖。
- GitHub Actions 执行 `npm ci`、`npx playwright install --with-deps chromium`，并在 Odoo CI 服务启动后运行浏览器表单 E2E。

### 影响

- 本地和 CI 使用同一套浏览器测试入口。
- 不提交 `node_modules`，通过 lockfile 保证依赖可复现。
- 远端 Actions 是否已实际运行仍需要推送到可执行远端后验证。
