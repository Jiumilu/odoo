## 2. 下一阶段计划

### 项目当前状态

系统运行健康，核心业务模块已安装，核心 smoke 已覆盖联系人、CRM、销售、采购、库存、制造、项目和权限边界。远端 CI、Browser 表单 E2E、认证后台 smoke 和核心流程覆盖率均已通过。

### 最大阻塞

当前无阻塞当前评分的 P0/P1。下一阶段最大风险是目标生产环境的外部邮件、短信、OAuth、Recaptcha、支付等真实凭证和连通测试尚未纳入本轮评分。

### 必须先修

- 在目标交付环境复跑当前远端 CI 等价门禁。
- 完成外部集成沙箱或真实连通证据。
- 完成生产备份、恢复、监控告警演练记录。

### 本轮已处理

- GPC-P0-001：CI 最小质量门禁已建立，远端 GitHub Actions 已通过。
- GPC-P0-002：核心业务流程闭环已完成。
- GPC-P0-003：部署、运维、回滚说明已补齐。
- GPC-P1-001：关键错误提示中文化已完成。
- GPC-P1-002：测试报告和 coverage 基线已建立。
- GPC-P1-003：项目级 changelog/release note 已补齐。
- GPC-P1-004：中文 README 和使用/测试说明已补齐。
- GPC-P1-005：默认用户时区本地化已完成。

### 可以后修

- 外部集成沙箱验证。
- 目标生产环境监控告警增强。
- 新增模块范围的单独验收矩阵。

### 不建议做

- 未清 P0 前新增大功能。
- 未定义验收矩阵前安装大量模块。
- 未建立 CI 前继续大规模中文化替换。
- 未有回滚/备份/监控方案前上线。

## 3. 三类专项行动

### 专项一：运行健康专项

目标：保留项目能稳定安装、启动、运行，有明确启动说明和环境变量。

GlobalCloud GPC 当前状态：运行健康已达标，但启动说明和环境文档未达标。

交付物：

- 中文 README。
- 部署说明。
- 运维说明。
- 健康检查命令固化到 CI。

### 专项二：核心功能闭环专项

目标：至少验证 3-5 条核心业务流程，消灭假按钮、mock 残留、断点流程。

GlobalCloud GPC 第一轮最小流程建议：

1. 用户登录 -> 后台首页 -> 应用导航。
2. Website 首页访问 -> 联系入口 -> 表单或联系方式验证。
3. Discuss 打开 -> 频道查看 -> 消息发送或只读权限边界验证。
4. 核心业务模块安装候选流程：销售/采购/库存任选一条，先确认能否安装，再做 create/read/update smoke。

### 专项三：测试证明力专项

目标：为核心流程补最小可用自动化测试或可复现 smoke test。

第一轮要求：

- CI 跑最小 Odoo test runner。
- 健康脚本成为固定 smoke test。
- 中文化 PO 检查成为固定质量门禁。
- 每条核心流程至少有可复现命令或手工验收步骤。
